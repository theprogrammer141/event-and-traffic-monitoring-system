# Articulate-AI — Frontend System Design & Architecture (RADIO Framework)

This document establishes the frontend system design and technical architecture for the **Articulate-AI** web application using the industry-standard **RADIO framework**:
1. **R**equirements (Functional & Non-Functional)
2. **A**rchitecture (Component Hierarchy, Data Flow, Routing)
3. **D**ata Model (Client Entities, State Shapes, Normalization)
4. **I**nterfaces (API Contracts, Component Props, Custom Hooks)
5. **O**ptimization (Performance, Accessibility, Vercel Guidelines, Resilience)

---

## 1. Requirements (R)

### A. Functional Requirements (FRs)

1. **Authentication & Session Management**:
   - User registration and login forms with real-time field validation.
   - JWT storage in `localStorage` with automatic hydration on initial application boot.
   - Immediate session expiration handling (auto-logout on 401 Unauthorized).
   - Multi-tenant tenant boundary: users only view events and insights submitted under their own account.

2. **Dashboard Overview (Telemetry & AI KPIs)**:
   - Real-time status heartbeat pill (`AI Engine: Active`, `Operational Status: Healthy`).
   - 4 primary metric KPI tiles:
     - **Total Incidents Recorded**
     - **Critical Alarms** (High priority incidents)
     - **AI Diagnoses Generated** (Total resolved/analyzed insights)
     - **System Health Index** (% calculation based on incident severity ratios)
   - Visual trend badges showing 24h activity.

3. **Live Incidents Explorer (Events)**:
   - Real-time table/list of ingested operational events.
   - Filter bar supporting multi-attribute filtering:
     - By Severity (`All`, `Critical`, `High`, `Medium`, `Low`).
     - By Event Type (`All`, `Server Crash`, `Traffic Spike`).
   - Server-side pagination controls (`page`, `limit`).
   - Direct link from an event to its corresponding AI diagnosis (if available).

4. **AI Diagnoses Feed (Insights)**:
   - Mission-control view of all AI diagnoses generated by the background LLM pipeline.
   - Diagnosis card anatomy:
     - AI Badge + Model used (`dots-studio/dots-3-note-preview:free`).
     - Associated incident chip (severity color dot, event type, relative timestamp).
     - Formatted AI Summary (observations and probable root causes).
     - **Interactive Remediation Checklist**: clickable action checklist allowing SREs/operators to check off steps in real-time.

5. **Event Ingestion Simulator**:
   - Interactive panel allowing developers/operators to trigger simulated incidents.
   - Presets for quick testing (e.g. *"Simulate Out-Of-Memory Crash"*, *"Simulate 10x Black Friday Traffic Spike"*).
   - Dispatches real `POST /api/v1/events` requests into the BullMQ queue and displays the returned `jobId` with immediate status feedback.

---

### B. Non-Functional Requirements (NFRs)

1. **Performance**:
   - First Contentful Paint (FCP) `< 1.0s` on local dev / standard broadband.
   - Cumulative Layout Shift (CLS) `< 0.05`: use fixed-dimension skeleton loaders and `tabular-nums` for all dynamic metrics.
   - 60fps animation budget: transitions animate `transform` and `opacity` only.
2. **Accessibility & Usability (Vercel Guidelines Compliance)**:
   - High-contrast text on dark backgrounds conforming to WCAG 2.1 AA standards.
   - Complete keyboard navigability (Tab, Shift+Tab, Enter, Space).
   - High-visibility focus indicators via `:focus-visible` (no default browser outline on click).
   - Screen reader live announcements using `aria-live="polite"` for background updates and alert toasts.
3. **Security**:
   - All authenticated requests include `Authorization: Bearer <token>`.
   - Zero raw `dangerouslySetInnerHTML`: all AI outputs, summaries, and error logs are sanitized and escaped as text.
4. **Responsiveness**:
   - Mobile-responsive layout (320px up to 4K ultra-wide monitors).

## 3. Data Model (D)

### Client-Side State Entities

```typescript
// 1. User & Authentication State
interface UserSession {
  user: {
    _id: string;
    fullName: string;
    email: string;
  } | null;
  token: string | null;
  isAuthenticated: boolean;
  isLoading: boolean;
}

// 2. Incident Event Entity (matches Event model)
interface EventItem {
  _id: string;
  eventType: 'Server Crash' | 'Traffic Spike' | 'Login' | 'SignUp';
  severity: 'Critical' | 'High' | 'Medium' | 'Low';
  source: string;
  message: string;
  submittedBy: string;
  createdAt: string;
  updatedAt: string;
}

// 3. AI Diagnosis Entity (matches Insight model + client checklist)
interface InsightItem {
  _id: string;
  event: EventItem; // Populated event document
  summary: string;
  recommendedActions: string[];
  model: string;
  createdAt: string;
  updatedAt: string;
  completedActions?: Record<number, boolean>; // Local checklist progress
}

// 4. Dashboard Metrics Aggregate
interface DashboardKPIs {
  totalEvents: number;
  criticalEvents: number;
  highEvents: number;
  totalInsights: number;
  healthScore: number;
  activeModel: string;
}

// 5. Query & Filter State
interface QueryFilter {
  page: number;
  limit: number;
  severity?: string;
  eventType?: string;
}
```

## 4. Interfaces (I)

### A. HTTP API Client Interface (`src/services/api.js`)

All communication with the backend is centralized in an API service that automatically manages the `Authorization` header:

```javascript
// Authentication
api.login({ email, password })        -> Promise<{ token, user }>
api.register({ fullName, email, password, confirmPassword }) -> Promise<{ token, newUser }>

// Events
api.getEvents({ page, limit, severity, eventType }) -> Promise<{ events, results, page }>
api.createEvent({ eventType, severity, source, message }) -> Promise<{ jobId, message }>

// Insights
api.getInsights({ page, limit, event }) -> Promise<{ insights, results, totalPages, totalResults }>
api.getInsightById(id)                  -> Promise<{ insight }>

// Health
api.getHealth()                         -> Promise<{ status, message }>
```

---

### B. Custom Hooks API

- **`useAuth()`**: Exposes `{ user, token, isAuthenticated, login, register, logout, loading }`.
- **`useEvents(filter)`**: Exposes `{ events, total, loading, error, refetch, createEvent }`.
- **`useInsights(filter)`**: Exposes `{ insights, total, totalPages, loading, error, refetch }`.

## 5. Optimization & Production Hardening (O)

### A. Performance Optimizations
1. **Smart Background Polling**:
   - Dashboard automatically polls for new events and insights every 15 seconds.
   - **Page Visibility API**: When the browser tab is hidden/inactive (`document.hidden === true`), polling is automatically paused to conserve client battery, network bandwidth, and server resources.
2. **Fixed Skeletons**:
   - Loading skeleton cards reserve explicit CSS dimensions (`min-height`) matching loaded cards, eliminating Cumulative Layout Shift (CLS = 0).
3. **Compositor Only Animations**:
   - Card hovers and drawer transitions animate `transform` and `opacity` strictly via CSS transitions (never `all`).

### B. Accessibility & Vercel Guidelines Checklist
- [x] All icon buttons include explicit `aria-label` attributes.
- [x] All decorative SVG icons include `aria-hidden="true"`.
- [x] Dynamic numeric counters use `font-variant-numeric: tabular-nums` to prevent horizontal jitter.
- [x] All headings utilize `text-wrap: balance` to eliminate orphan words.
- [x] Focus states use `:focus-visible` with a double-ring outline replacement.
- [x] Form controls have explicit `<label htmlFor="...">` bindings.
- [x] Error states and asynchronous updates announce to assistive technology via `aria-live="polite"`.
- [x] Respects `@media (prefers-reduced-motion: reduce)`.
